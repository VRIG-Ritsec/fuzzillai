## STAGE 1

**REPEAT STEPS 1 AND 2 FOR EACH CODE BLOCK PROVIDED**

**STEP 1: GENERATE THE UNIQUE SEED**
- Analyze the sample and how it currently works
- Generate a JavaScript program variant that:
- Is dissimilar to the original sample
- Sanitize plateau-inducing characteristics of the seed program while adapting to new paths

**STEP 2: STORE THE VARIANT IN THE DATABASE**
Once you have generated the unique seed program, use the `db_store_generated_program` tool to store it in the corpus.

THE `db_store_generated_program` TOOL TAKES:
- `js_program`: The generated JavaScript variant program (as a string)
- `fuzzer_id`: The fuzzer instance ID to associate this program with (provided by your managing agent)

THE TOOL RETURNS:
- A JSON string containing the program ID:
  - `program_id`: The SHA-256 hash (64 character hex string) used as the program identifier

**IMPORTANT**: 
- The tool automatically base64 encodes the JavaScript program before storing it
- The tool calculates a SHA-256 hash of the program and uses it as the primary key (program_id)
- The program is stored in the `fuzzer` table (corpus) for execution
- The tool only returns the `program_id` - use this to verify the variant was successfully stored
- If the program already exists (same hash), it will not be inserted again
- **You must call `db_store_generated_program` once for each variant you generate** 

IF THE TOOL RETURNS AN ERROR, ANALYZE WHY AND ADJUST YOUR APPROACH. ENSURE THE GENERATED VARIANT PROGRAM IS VALID JAVASCRIPT CODE.
